# 개발 방법론 초안

기준일: 2026-11-09. 근거는 PLAN v6.2 0·2·3·10·11장, 로컬 AGENTS.md,
현재 구현·시험, Git 이력 및 아래 실측 메모다. 이 문서는 이미 수행된 확인과
앞으로 적용할 절차를 구분한다. 새로운 승인 체계나 미실행 시험의 합격을 만들지 않는다.

## 개발 절차

| 단계 | 수행 내용 | 확인 자료·출구 조건 |
|---|---|---|
| 계획 | PLAN 0·3·5장과 해당 WP를 읽고 범위·예산·미확인 항목 지정 | 요구사항 ID, 원자료 형식, 수정 금지 영역 확인 |
| WP 단위 구현 | 재사용할 하네스·도구를 먼저 읽고 요청된 기능만 구현 | 범위 밖 모듈 선행 구현 금지; 세부 변경은 시험으로 검증 |
| PC 확인 | 도구 설치·설정·HTTP·토크나이저 등 일반 환경 검증 | 실제 실행 결과만 기록; mock 성공을 HW 확인으로 쓰지 않음 |
| HW 확인 | H0 경로 연결 후 H1~H8의 장치·수집·시간 의미 확인 | 버전·원자료·로그 근거, 남은 TODO와 H번호 |
| 실측 | 고정된 조건·warm-up 분리·쌍 검사·계측 모드로 실행 | 서비스 설정, 커밋, 원자료, 경계·span·이벤트 보존 |
| 분석 | 원자료 → 계측 검증 → 지표 계산 → 산출물 저장 | run_status와 analysis_status 분리; 실패·결측 사유 유지 |
| 검토·수정 | AI 도구의 diff·시험·보고를 사람이 검토하고 수정 요구 | 수치 정의와 원인 근거를 재검토; fixture 기대값을 맞춰 바꾸지 않음 |

이 작업의 진행 기록에는 사람이 줄 수 상한·검증 보존·제외 범위를 조정하고,
AI 코딩 도구가 구현·시험·보고한 사례가 있다. 이를 자동 승인이나 별도 담당자 서명 완료로
해석하지 않는다. 최종 납품의 승인·보안 검사 완료 여부는 이 초안의 주장 범위가 아니다.

## 형상 관리와 실행 격리

| 항목 | 확인된 규칙·현황 | 적용 방법 |
|---|---|---|
| 기준 브랜치 | PLAN과 현재 작업 브랜치는 main | 실행 시 HEAD를 기록하고 분석 코드의 HEAD와 구분 |
| 커밋 표기 | 최근 이력에 feat(hetero), fix(hetero), refactor(hetero), chore(hetero) 사용 | 현재 관례를 따름; 필수 commit-msg 규약으로 강제된다는 근거는 없음 |
| 변경 묶음 | 요청된 WP 또는 결함 수정 범위 | 파일·행 수·시험·계획 차이를 보고; 관련 없는 변경 혼합 금지 |
| 실측 worktree | `hetero-pdd-run` 이름의 별도 worktree, 조회 시 detached HEAD | 사람이 선택한 커밋을 clean 상태로 실행; 개발 트리의 미커밋 변경과 분리 |
| clean 검사 | orchestrate.verify_environment가 환경·저장소 상태 검사 | 무시 파일만 있는 경우 통과, 추적 파일 변경은 실패하는 시험 유지 |
| 로컬 자료 | `.notes/`, AGENTS.md는 로컬 전용 | 커밋·강제 add 금지; 원본 harness_original 수정 금지 |
| 결과·설치 | 저장소 밖 인자/환경변수로 위치 지정 | run, sweep, 모델, venv, 바이너리, 캐시·로그를 저장소에 넣지 않음 |

Git worktree 조회 당시 main과 실측 worktree는 같은 `d1b715c`를 가리켰다.
이는 과거 모든 측정이 그 커밋에서 실행됐다는 뜻이 아니다. H0 메모에는
실행 당시 커밋과 수정 후 재분석 당시 커밋이 서로 다른 사례가 기록되어 있다.
새 결과를 기존 결과에 덮어쓰지 않는다. sweep 재실행은 성공 결과를 건너뛰고
실패한 실행에는 새 접미사 경로를 사용한다.

실측 전용 worktree 준비는 기존 worktree 존재 여부를 먼저 확인한 뒤 수행한다.
필요하면 `git worktree add --detach <실측-worktree> <검증할-커밋>`으로 별도 체크아웃을 만든다.
경로는 사용자가 지정한다. 이 문서 작성 작업에서는 worktree나 커밋을 새로 만들지 않았다.

## 품질 관리

AGENTS.md의 최신 완료 조건을 적용한다. PLAN 0장의 all-files 규정은
이후 변경·신규 파일 대상으로 조정되었으므로 현재는 다음 명령을 사용한다.
명령은 저장소 루트에서 실행한다.

```bash
python3 -m unittest discover -s tests/hetero
python3 -m unittest discover -s tests/pdd
pre-commit run --files $( { git diff --name-only upstream/main...HEAD; git diff --name-only; git ls-files --others --exclude-standard; } | sort -u | while read -r f; do [ -e "$f" ] && echo "$f"; done )
```

중복 경로를 제거하고 삭제 파일을 제외하되 검사 대상의 변경·신규 파일 집합은 유지한다.
기존 코드의 범위 밖 훅 오류는 무관한 코드 수정으로 숨기지 않고 보고한다.
조건부 skip은 합격한 HW 검증과 구분해 사유·환경변수와 함께 기록한다.

| 품질 항목 | 방침 |
|---|---|
| 계산 정확성 | 클라이언트 fixture 재현, 기대 ID, 경계·귀속·에너지·PER-001 계산 집중 |
| 시험 형태 | 여러 경우는 입력/기대값 표와 반복문; 준비 코드 공유 |
| 실행기 | 정상 순서 1개와 예외 정리 1개를 기본으로 확인 |
| mock 자체 | 상세 동작 시험 확대 금지; 최소 스모크만 유지 |
| 시각화·연산자 | 산출물 생성 스모크 중심; 실제 장치 의미는 HW 확인 |
| 엔진 훅 | 비활성 경로, 시간·누적·flush, 조건부 import 확인; 성능 무변화는 별도 실측 문제 |
| 줄 수 | wc -l, 빈 줄·주석 포함; 요청 상한의 120% 이내 초과는 진행 후 사유 보고 |
| 상한 초과 | 120% 초과가 예상되면 구현 전 중단·보고; 기능·검증을 빼서 맞추지 않음 |
| 로그 | `<UTC ISO8601> [<run_id>] [<component>] <message>`; 외부 도구 로그 원문 보존 |
| 경로·실행 | 절대경로 리터럴, shell=True, eval, 문자열 조립 셸 실행 금지 |

tools/hetero·tests/hetero Python은 SPDX Apache-2.0 한 줄로 시작한다.
엔진 파일의 기존 라이선스 헤더는 보존한다. tools/pdd·tests/pdd·기존 PDD proxy/CI는
수정 금지 대상이며 tests/pdd는 회귀 확인에만 사용한다.

## 실측에서 확인된 결함의 처리 사례

| 결함 | 근거·진단 | 수정 및 검증 | 남은 확인 |
|---|---|---|---|
| H0 KV 이벤트 연결 실패 | OTEL은 외부 ID, 엔진은 끝에 8자리 hex 접미사 | fullmatch로 끝 접미사만 제거; unmatched·중복 시험; H0 양 decoder KV 3종 연결 | 다른 요청 형식 일반화 및 monitor 출력 비교 미확인(H0) |
| M14a 기타 음수 | WP7b H0 −37.553436%; 큐·KV·layout 등 시간이 겹침 | 서비스 구간 안 우선순위 배타 분할; 합=1·기타≥0·손계산 시험 | M06~M10의 원값은 보존; M12는 별도 미구현 |
| PER-001 연속 ON 포트 실패 | per001_r1b 원본·재시도 모두 두 번째 ON에서 Address already in use; TIME_WAIT는 추정 | SO_REUSEADDR bind, 최대 30초 대기; stop의 wait 유지; r3 4블록 정상 완료 | 당시 소켓 상태가 없어 TIME_WAIT 인과는 미확인(H8); 1차 측정 합격 |
| PER-001 기동 전 거부 | per001_r2 서비스 로그 dirty=True, runs 0건 | 변경 커밋 후 b776289의 r3 기동 성공; clean 검사 유지 | 기동 실패를 성능 불합격으로 해석하지 않음 |
| GPU deep gzip 손상 | H6 stop_profile 10초 timeout, 손상 footer; export 중 종료 가능성은 추정 | stop 뒤 새 파일 크기 3초 안정·gzip EOF 확인, 최대 120초; 실패 사유·원본 보존 | 수정 후 실제 GPU export·callback 오류 해소 미확인(H6) |
| step.device 누락 | H4/H6의 모든 관측 device=null; SDK report 수집 경로 확인 | T06 분모를 전 decode step 호스트 span으로 대체, 하한 추정 표기 | SDK 누락 원인·device 의미·copy_ 완료 동기성 미확인(H4) |

원인과 추정은 분리한다. 예를 들어 바이트 증가와 h2d_ns 증가만으로 동기 복사를 확정하거나,
UCX 백엔드 로그만으로 TCP/RDMA lane을 단정하지 않는다.
결함 수정 후 기존 숫자와 비교할 때 원자료·fixture 기대값을 수정하지 않고 계산 쪽을 고친다.
재분석은 workload summary를 갱신할 수 있지만 원래 run.json의 실행 이력을 성공으로 덮지 않는다.

## PC·HW 증거의 범위

| 자료 | 문서에서 사용할 수 있는 사실 | 확대 해석하지 않을 내용 |
|---|---|---|
| H0 메모 | 역할별 span·KV 연결, host buffer, 정상 종료 이벤트 보존 | 강제 종료 영속성, monitor와 토큰 동일성 |
| S1/S2 재현 | 요청한 40개 성능 비교 값이 10% 이내, 장치 UUID/PCI·NIXL 차분 | 환경 전체 동일, H2 장시간/CPU 비용 완료, count의 일반 전송 단위 |
| WP7b·M14a 메모 | 계측 유효성·coverage·중첩 결함과 수정 | 짧은 H0에 자원/에너지 대표성 부여 |
| HW_H4_H6_H7·H6_fix | H7 반복 기동 단축·16/16 출력 일치, 4B 기동, device 누락, 온라인 MP 제약 | 모든 캐시 조건 호환, NPU 장치 연산 확보 |
| WP11 메모 | 쌍 검사·표·데이터셋 구현 및 합성 시험, 실행 시간 추정 | 전체 실제 스윕 완료; 메모의 S9는 이후 오프라인 WP9로 대체됨 |
| PER001 원본·정리 메모 | per001_r3 overhead.json/md의 4블록 PASS, r1b 포트 중단·r2 dirty 기동 실패 | PER-001 1차 측정: 합격(최종 측정은 코드 확정 후) |

`.notes/PER001_1차_2026-11-07.md`는 지정된 세 시도의 원본 결과에서 정리했다.
r3의 d_tp 평균은 −0.049765112%, 90% CI [−0.182904110%, 0.083373887%],
d_lat 평균은 −0.037642756%, CI [−0.105785723%, 0.030500210%]다.
두 상한이 5% 이하여서 4블록에서 합격했다. 최종 코드 재측정은 미확인(H8)이다.

H번호가 없는 관리 사항에 임의 H번호를 부여하지 않는다. 예를 들어 커밋 메시지의
강제 규칙·PR 승인 인원·최종 보안 검사는 확인된 운영 규칙처럼 쓰지 않는다.
계획의 납품 완료 조건은 PT-001 PASS, 필수 산출물·그림·4분류 시험 보고다.
현재 단위시험 PASS나 이 문서 초안 작성을 납품 완료로 간주하지 않는다.

## 작업 보고 양식

1. 변경 파일과 요약.
2. 실행 시험·결과·조건부 skip 또는 생략(HW 확인으로 대체).
3. 계획과 다른 구현 및 사유.
4. 남은 TODO(verify), 필요한 PC/HW 항목.
5. wc -l 코드량과 요청 예산 대비.

실행 환경의 실제 Python·모델 경로는 개인별 설정에서 받는다.
문서·코드에는 저장소 상대 경로나 `<설치 위치>` 표기만 사용한다.
